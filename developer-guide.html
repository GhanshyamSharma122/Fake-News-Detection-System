DEVELOPER GUIDE / VERSION 1

How NewsLens works

NewsLens is a supervised NLP application that screens news text for patterns associated with misleading examples. It provides a risk signal and reasons for review; it does not prove whether a claim is true.

1. Quick start

Install dependencies

Use Python 3.10 or newer from the project folder:

python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

Prepare and train

Place a legitimate labelled CSV at data/raw/news.csv. It must contain text and label columns. See data/README.md for the accepted labels and data requirements.

python training/train_model.py --input data/raw/news.csv

Start the application

python server.py

Open http://127.0.0.1:5000 in a browser. The model must be trained before analysis is available.

2. End-to-end workflow

DATASET ↓ Validate rows and labels → Stratified train/test split ↓ spaCy tokenization → Word TF-IDF + character TF-IDF ↓ Logistic Regression training → Metrics + model.joblib ↓ Browser text → POST /api/analyze → Model probability ↓ Risk score + language signals → Human verifies original sources

Training: The training script validates the dataset, creates word and character features, trains a balanced Logistic Regression classifier, evaluates it on held-out data, and saves a model artifact.

Inference: The Flask API loads the saved artifact, validates the submitted text, calculates the probability of the misleading class, and returns a label, score, metrics, and supporting signals.

Review: The user checks the article’s publisher, author, date, evidence, and independent sources before making a decision.

3. High-level design (HLD)

ComponentResponsibility
Web UIAccepts news text, displays the score, language signals, warnings, and project documentation.
Flask APIServes the page, validates requests, exposes health status, and performs inference.
NLP pipelineUses spaCy tokenization and TF-IDF feature extraction for words and character patterns.
ClassifierLogistic Regression estimates the misleading-language probability.
Model artifactStores the trained pipeline and metadata such as metrics and dataset hash.
Human reviewerPerforms final fact-checking; the system is not an autonomous truth engine.

4. Low-level design (LLD)

Training modules

  • load_dataset() reads and validates the CSV.
  • tokenize_text() in nlp_utils.py supplies the shared spaCy tokenizer.
  • FeatureUnion combines word n-grams and character n-grams.
  • LogisticRegression trains the binary classifier.
  • classification_report calculates evaluation metrics.
  • joblib.dump() writes the versioned model artifact.

API modules

  • GET / serves the user interface.
  • GET /api/health reports whether a valid model is loaded.
  • POST /api/analyze accepts {"text":"..."} and returns the prediction.
  • language_signals() adds readable indicators such as sensational words, emphasis, evidence terms, and text statistics.

Analysis request

1. User enters text 2. Browser sends JSON to POST /api/analyze 3. API rejects empty or oversized input 4. Saved pipeline transforms text into TF-IDF vectors 5. Classifier returns probability 6. API maps probability to a cautious label 7. Browser renders score, signals, and warning

5. How to analyse news

  1. Start the trained server.
  2. Open the NewsLens home page.
  3. Paste a headline or short article into the text box.
  4. Select Analyse text.
  5. Read the risk score and the signals that influenced the result.
  6. Verify the original source and at least one independent reliable source.

6. Developer notes

  • Do not train on the small example data or claim high accuracy without a real labelled dataset.
  • Do not interpret a high score as proof of fake news or a low score as proof of truth.
  • Keep training and test articles separate to prevent data leakage.
  • Record dataset source, licence, label definition, class distribution, and metrics in the report.
  • For college deployment, use HTTPS and a production WSGI server such as Gunicorn.
  • Before public use, add authentication, rate limiting, monitoring, model versioning, and a reviewed data-retention policy.
