DEVELOPER GUIDE / VERSION 1

How NewsLens works

NewsLens is a supervised NLP application that screens news text for patterns associated with misleading examples. It provides a risk signal and reasons for review; it does not prove whether a claim is true.

1. Quick start

One-click Windows start

Double-click run.bat. It creates the virtual environment, installs dependencies, trains the model if models/newslens.joblib is missing, and starts the server.

Install dependencies

Use Python 3.10 or newer from the project folder:

python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

Prepare and train

Place a legitimate labelled CSV at data/raw/news.csv. It must contain text and label columns. See data/README.md for the accepted labels and data requirements.

For the downloaded Kaggle files stored in this project, run:

python training/train_model.py --input data

The trainer reads data/Fake.csv and data/True.csv, combines title and body text, and assigns the labels automatically.

Start the application

python server.py

Open http://127.0.0.1:5000 in a browser. The model must be trained before analysis is available.

2. Recommended genuine datasets

Recommended starting point: ISOT Fake News Dataset

For this project’s binary article-level classifier, use the ISOT Fake News Dataset download. It contains separate Fake.csv and True.csv files with article title, body text, subject, and date. The trainer accepts the downloaded folder directly, combines title and body, assigns labels from the filenames, and records a dataset hash in the model metadata. Document the dataset’s CC BY-NC-SA 4.0 licence and keep the original source information in your report.

Research benchmark: LIAR

For claim-level fact checking, use the LIAR benchmark paper. It contains about 12.8K manually labelled short statements collected from PolitiFact and uses six truthfulness labels, not a simple fake/real label. It is excellent for an academic experiment, but requires a deliberate label mapping or a six-class model.

Advanced option: FakeNewsNet

For a larger research extension, use the FakeNewsNet repository. It includes article-level samples and identifiers for social context. The complete collection cannot simply be redistributed because of publisher copyright and platform privacy policies, so follow the repository instructions and record exactly which subset was used.

Recommendation: use ISOT for the first binary AAT implementation, use LIAR as a comparison or discussion dataset, and do not mix datasets without checking their different label meanings and time periods.

3. Core concept, explained

What problem are we solving?

A person enters a news headline or article. The system estimates whether its language resembles examples labelled as misleading in the training data. This is a pattern-recognition problem, not a truth machine: the model does not browse the web, check evidence, or understand events like a human fact-checker.

What does the model learn?

First, the text is converted into numbers. Bounded word TF-IDF gives higher weight to informative words that are uncommon across the dataset. Limiting the vocabulary makes the system practical to train and deploy on a college computer while retaining the core NLP concept. These numbers form a feature vector for each article.

How does classification work?

Logistic Regression learns weights for those features using labelled training examples. A positive weight means a feature is associated with the misleading class in the training data; a negative weight means it is more associated with the credible class. NewsLens trains both an article model and a headline model. Inputs up to 60 words use the headline model; longer text uses the article model. At prediction time, the selected model produces a probability that becomes a cautious risk score.

Why split training and testing data?

The model must be tested on articles it never saw during training. Otherwise, the score measures memorisation rather than generalisation. A stratified split keeps the class proportions similar, while a separate validation set or cross-validation can be used during model selection. Duplicate articles, syndicated copies, and articles from the same event must be handled carefully to prevent data leakage.

How do we judge quality?

Accuracy alone can be misleading when classes are imbalanced. Precision answers “when the system flags an article, how often is that flag correct?” Recall answers “of the misleading examples, how many did it find?” F1 balances both. The report should include a confusion matrix, per-class results, dataset balance, error examples, and results on a different time or topic split.

Why is human verification still required?

A model can learn publisher identity, political vocabulary, writing style, or dataset artefacts instead of factuality. A legitimate opinion, satire, translated article, or breaking story may be flagged. Therefore the output is a triage signal: inspect the original source, author, publication date, cited evidence, and independent reporting before sharing.

4. Complete training process

Step 1: Choose and inspect the data

The project reads data/Fake.csv and data/True.csv. The filename supplies the binary label, while the title and article body supply the text. The loader ignores empty rows and combines the title with the body for the article model. It also keeps the title separately for the headline model.

Step 2: Validate the input

The trainer checks that the dataset exists, contains at least 1,000 usable rows, and contains exactly two recognised labels. It reports the class distribution. This prevents a tiny or one-class file from being mistaken for a meaningful training run.

Step 3: Split before learning

The complete dataset is split into 80% training data and 20% held-out test data using stratification and random seed 42. The classifier sees only the training portion during fitting. The test portion is used once for an unbiased first evaluation.

Step 4: Tokenize and create features

Each text is converted to tokens using spaCy when available. The tokenizer fallback is used only when spaCy is unavailable. TF-IDF then converts the tokens into a bounded numerical vocabulary of informative words. Rare and overly common terms are controlled using minimum and maximum document-frequency settings.

Step 5: Train two classifiers

NewsLens fits one balanced Logistic Regression classifier on full article text and another on headlines only. Class balancing reduces the effect of the small difference between the two dataset classes. The models learn feature weights from labelled examples; they do not browse the internet or independently verify facts.

Step 6: Evaluate

Predictions on the held-out rows are compared with their labels. Accuracy measures total correct predictions. Precision measures how many flagged items were actually in the flagged class. Recall measures how many flagged-class items were found. F1 combines precision and recall into one balanced score. Separate metrics are saved for the article and headline models.

Step 7: Save the artifact

The two fitted pipelines are saved to models/newslens.joblib. A JSON metadata file stores the dataset name, SHA-256 hash, label definition, row counts, class distribution, creation time, and evaluation results. The API loads this artifact; it does not train during normal startup.

Step 8: Use the trained model

When the user submits text, the API selects the headline model for inputs up to 60 words and the article model for longer text. It transforms the text using the saved vocabulary, obtains the misleading-class probability, maps it to a cautious label, and returns the result with supporting language signals.

When does training happen?

run.bat trains only when models/newslens.joblib does not exist. If the model is already present, it prints “Existing trained model found. Skipping training.” To intentionally retrain after changing the dataset or code, run python training/train_model.py --input data manually.

5. End-to-end workflow

DATASET ↓ Validate rows and labels → Stratified train/test split ↓ spaCy tokenization → bounded Word TF-IDF ↓ Logistic Regression training → Metrics + model.joblib ↓ Browser text → POST /api/analyze → Model probability ↓ Risk score + language signals → Human verifies original sources

Training: The training script validates the dataset, creates bounded word features, trains a balanced Logistic Regression classifier, evaluates it on held-out data, and saves a model artifact.

Inference: The Flask API loads the saved artifact, validates the submitted text, calculates the probability of the misleading class, and returns a label, score, metrics, and supporting signals.

Review: The user checks the article’s publisher, author, date, evidence, and independent sources before making a decision.

7. Low-level design (LLD)

Training modules

  • load_input() reads either a normal labelled CSV or the ISOT Fake.csv/True.csv folder.
  • tokenize_text() in nlp_utils.py supplies the shared spaCy tokenizer.
  • TfidfVectorizer creates bounded word unigram features.
  • Two LogisticRegression models are trained: one for full articles and one for headlines.
  • classification_report calculates separate evaluation metrics.
  • joblib.dump() writes both pipelines into the model artifact.

API modules

  • GET / serves the user interface.
  • GET /api/health reports whether a valid model is loaded.
  • POST /api/analyze accepts {"text":"..."} and returns the prediction.
  • language_signals() adds readable indicators such as sensational words, emphasis, evidence terms, and text statistics.

Analysis request

1. User enters text 2. Browser sends JSON to POST /api/analyze 3. API rejects empty or oversized input 4. Saved pipeline transforms text into TF-IDF vectors 5. Classifier returns probability 6. API maps probability to a cautious label 7. Browser renders score, signals, and warning

8. How to analyse news

  1. Start the trained server.
  2. Open the NewsLens home page.
  3. Paste a headline or short article into the text box.
  4. Select Analyse text.
  5. Read the risk score and the signals that influenced the result.
  6. Verify the original source and at least one independent reliable source.

Local verification completed

The downloaded folder contained 44,898 usable articles. The model used 35,918 training rows and 8,980 held-out rows, producing 0.9931 accuracy and 0.9934 F1 on a random stratified split. A real row from True.csv scored 1, and a real row from Fake.csv scored 100. These results are useful for demonstrating the flow, but they are not proof of real-world accuracy; publisher and topic artefacts can make random splits optimistic.

9. Developer notes

  • Do not train on the small example data or claim high accuracy without a real labelled dataset.
  • Do not interpret a high score as proof of fake news or a low score as proof of truth.
  • Keep training and test articles separate to prevent data leakage.
  • Record dataset source, licence, label definition, class distribution, and metrics in the report.
  • For college deployment, use HTTPS and a production WSGI server such as Gunicorn.
  • Before public use, add authentication, rate limiting, monitoring, model versioning, and a reviewed data-retention policy.

10. Smoke-test file

Verified headlines for a quick demonstration are stored in data/test_cases.csv. Paste each text value into the detector and compare it with expected_label. The recorded score is informational and can change after retraining.
